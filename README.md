# CellVeilXL 2.0

CellVeilXL шифрует данные из выбранного диапазона Excel и прячет их в оформлении другого листа. Получается обычный файл `.xlsx`: его текст остаётся видимым, а скрытые данные записываются через небольшие изменения цвета, наклона и шрифта.

Для работы в Excel нужен только **`cellveilxl.bas`**. В нём собран весь код. Он не вызывает Windows API, Python или внешние программы. Python нужен отдельно — для создания ключей, в том числе на другом компьютере.

## Что изменилось в версии 2.0

- Можно скрывать прямоугольный диапазон, а не одну ячейку.
- Для шифрования и расшифровки используются разные ключи.
- Есть два режима: короткий демонстрационный ключ и полный ключ X25519.
- Вместо RC4 используется AES-256-CTR. Ключ для него получается через DH или X25519 и HKDF-SHA256.
- Сохраняются кириллица, emoji, числа, логические значения, пустые ячейки и числовые форматы, включая даты.
- Для скрытия используются цвет, наклон и четыре похожих шрифта. Полужирные заголовки не меняются.
- Результат создаётся в отдельной книге без исходного листа с секретами, ключей и макросов.

## Какие файлы нужны

| Файл | Для чего нужен |
|---|---|
| `cellveilxl.bas` | Весь код, который нужно импортировать в Excel |
| `python/keygen.py` | Создание открытого и закрытого ключей |
| `python/requirements.txt` | Библиотека Python для генератора ключей |
| `tests/` | Проверки для разработчика. Для обычной работы эта папка не нужна |

## Режимы и ограничения защиты

| Режим | Длина открытого ключа | Алгоритм |
|---|---:|---|
| `demo` | 15 символов | DH с небольшой 87-битной группой |
| `production` | 43 символа | X25519 |

Открытый ключ можно передавать другим людям. Он нужен для шифрования. Закрытый ключ нужен для расшифровки — его следует хранить у себя. Ключи вводятся с учётом регистра: большая и маленькая буквы считаются разными символами.

У этой программы есть существенное ограничение. По условию она использует только средства Excel, поэтому случайные числа берутся из `Rnd`. Этот генератор не предназначен для криптографии. Из-за него даже режим `production` нельзя считать полноценным решением для надёжной защиты конфиденциальных данных. Название режима обозначает размер и тип ключа, а не гарантию стойкости всей программы. Режим `demo` дополнительно ослаблен коротким ключом.

Проверка целостности отключена: контрольных сумм и MAC нет. Программа может заметить неверный ключ или повреждение по ошибке разбора, но обнаруживает их не во всех случаях. Скрытие в оформлении также не гарантирует, что данные нельзя заметить при анализе файла. Независимый аудит этой реализации не проводился.

## Как создать ключи

На компьютере с Python 3.10 или новее выполните команды из папки проекта:

```powershell
python -m pip install -r python/requirements.txt
python python/keygen.py --mode production --output production-keys.json
```

Для демонстрационного режима:

```powershell
python python/keygen.py --mode demo --output demo-keys.json
```

Открытый ключ появится в консоли. Оба ключа будут сохранены в JSON-файле:

- `public_key` — открытый ключ;
- `private_key` — закрытый ключ;
- `mode` — выбранный режим.

Существующий файл ключей не перезаписывается. JSON с закрытым ключом не нужно передавать вместе с открытым ключом. Excel не читает JSON: в ячейку вводится только нужная строка ключа.

## Как подготовить Excel

Нужен настольный Excel с поддержкой VBA. Программа проверена в Windows Excel 16.0. В браузерной версии Excel макросы не работают.

1. Создайте книгу и сохраните её как `.xlsm`.
2. Откройте редактор VBA клавишами `Alt+F11`.
3. Выберите File → Import File и импортируйте **`cellveilxl.bas`**. Другие файлы импортировать не нужно.
4. Создайте листы `List1` и `List2`.

Если ранее использовали версию с несколькими модулями, сначала удалите из VBA старые `cellveilxl`, `cv_crypto` и `cv_field`. Иначе Excel может сообщить о повторяющихся именах функций.

Код можно вставить вручную в стандартный модуль через Insert → Module. В этом случае пропустите первую строку файла — `Attribute VB_Name`.

В начале кода находятся настройки:

```vb
Private Const MAGIC_BYTE_0 As Byte = 67
Private Const MAGIC_BYTE_1 As Byte = 86
Private Const MAGIC_BYTE_2 As Byte = 88
Private Const MAGIC_BYTE_3 As Byte = 51
Public Const CRYPTO_MODE As String = "production"
Private Const SOURCE_RANGE As String = "A1:A10"
Private Const PUBLIC_KEY_CELL As String = "B1"
Private Const PRIVATE_KEY_CELL As String = "B2"
Private Const OUTPUT_CELL As String = "D1"
Private Const HOST_RANGE As String = ""
```

`SOURCE_RANGE` задаёт диапазон с секретными данными, например `A3:F20`. `OUTPUT_CELL` — верхняя левая ячейка, с которой начнётся восстановление. `HOST_RANGE` ограничивает область носителя; пустая строка означает всю используемую область листа.

Исходный диапазон и область вывода не должны пересекать ячейки ключей. Если выбираете широкий диапазон, перенесите ключи или вывод в другое место. Имена листов меняются в константах `SCR_SHEET` и `HOST_SHEET`.

## Как скрыть данные

1. Заполните исходный диапазон на `List1`.
2. Введите открытый ключ в `List1!B1`.
3. На `List2` подготовьте обычный документ с текстом. Он будет носителем. Не размещайте в нём сами секретные сведения.
4. Проверьте, что `CRYPTO_MODE` совпадает с режимом, выбранным при генерации ключей.
5. Нажмите `Alt+F8` и запустите `EmbedScr`.
6. Макрос создаст новую книгу с одним листом. Сохраните её как `.xlsx`.

Исходная книга останется у вас. В результат не копируются лист с секретами, ключи и VBA. Закрытый ключ для скрытия не нужен.

Если места в документе недостаточно, программа сообщит, сколько бит нужно и сколько доступно. В таком случае увеличьте количество текстовых ячеек или уменьшите исходный диапазон.

## Как извлечь данные

1. Откройте книгу `.xlsm` с модулем `cellveilxl`.
2. Установите тот же режим и тот же `HOST_RANGE`, которые использовались при скрытии.
3. Введите закрытый ключ в `List1!B2`.
4. Запустите `ExtractScr` через `Alt+F8` и выберите файл `.xlsx` с носителем.
5. Данные восстановятся начиная с `OUTPUT_CELL`, с исходным числом строк и столбцов.

Существующие значения в области вывода будут заменены. Открытый ключ для извлечения не нужен.

До извлечения не меняйте текст и порядок ячеек носителя, цвета, наклоны и шрифты. Это может повредить скрытые данные.

## Как устроено скрытие

Сначала программа записывает размеры исходного диапазона, значения ячеек и их числовые форматы в UTF-16. Затем создаёт временную пару ключей и получает общий секрет с открытым ключом получателя. Через HKDF-SHA256 из него получается ключ AES, которым шифруются данные.

Первые 4 байта скрытого потока по умолчанию — ASCII-литерал `CVX3`: `67, 86, 88, 51` (hex: `43 56 58 33`). Их можно задать константами `MAGIC_BYTE_0`–`MAGIC_BYTE_3` в начале `cellveilxl.bas`, указав целые значения от 0 до 255. Изменение этих байтов может снизить вероятность детекции по фиксированной сигнатуре `CVX3`, но не исключает обнаружение по другим признакам. Для скрытия и извлечения нужны одинаковые значения всех четырёх констант; для ранее созданных файлов сохраните использованные значения.

В пакет входят служебный заголовок, режим, длина, временный открытый ключ, nonce и зашифрованные данные. Закрытого ключа получателя в пакете нет. При извлечении программа выполняет обратные действия с закрытым ключом.

Пакет записывается в оформление:

- **Цвет:** 6 бит на символ. Каждый RGB-канал меняется максимум на 3 из 255.
- **Наклон:** 2 бита на ячейку. Обычный горизонтальный текст получает наклон от 0 до 3 градусов.
- **Шрифт:** 2 бита на ячейку. Используются Arial, Calibri, Segoe UI и Tahoma. Размер шрифта сохраняется.

Эти шрифты похожи, но имеют разную ширину символов. На компьютере просмотра они должны быть установлены. При подготовке документа оставляйте достаточно места по ширине и высоте ячеек, чтобы текст не обрезался.

Общая вместимость в битах:

```text
4 × число пригодных ячеек + 6 × число символов в них
```

Часть места занимают параметры шифрования и описание диапазона. Даже пустые ячейки источника требуют метаданных.

## Что сохраняется и что не поддерживается

В качестве носителя не используются полужирные заголовки, числа, формулы, ошибки, пустые и объединённые ячейки, вертикальный текст и ячейки с условным форматированием. В новой книге формулы документа заменяются их значениями; получившиеся текстовые ячейки могут участвовать в скрытии.

В итоговый документ переносятся значения, оформление ячеек, ширины колонок, высоты строк и состояние скрытых строк и столбцов. Рисунки, диаграммы, настройки печати и другие объекты не переносятся.

При восстановлении возвращаются значения и числовые форматы. Формулы источника сохраняются как вычисленные значения. Ошибки Excel и объединённые ячейки источника не поддерживаются. Текст, начинающийся с `=`, остаётся текстом и не выполняется как формула.

Можно выбрать один прямоугольник до 200000 ячеек. Размер зашифрованного пакета ограничен 1 MiB. Вывод в защищённый лист, объединённые ячейки и ячейки с формулами массива запрещён. Большие документы могут обрабатываться медленно из-за посимвольного изменения оформления.

В версии программы 2.0 используется формат пакета CVX3. Он несовместим со старой версией на RC4. Контрольные суммы старого формата удалены.

## Проверки для разработчика

Папка `tests` содержит проверки SHA-256, X25519, AES-256-CTR, HKDF и обоих режимов ключей. Также проверяются сохранение и повторное открытие `.xlsx`, восстановление диапазонов и обработка ошибок.

Запуск из папки проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ./tests/run_excel_tests.ps1
```

Для тестов нужны установленный Excel и Python с зависимостями генератора. Скрипт управляет Excel через COM только во время проверки. Он временно включает доступ к VBA-проекту и затем возвращает прежнюю настройку. Пользовательские макросы от этого скрипта не зависят. Тестовые документы сохраняются в `.test-output`.
