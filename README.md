# CellVeilXL

CellVeilXL шифрует диапазон Excel и прячет его в оформлении другого листа — в цвете текста, наклоне и шрифтах. Результат сохраняется как обычный `.xlsx` без исходного листа, ключей и макросов.

Для работы нужен настольный Excel с VBA. Python используется только для создания ключей и может быть установлен на другом компьютере.

## Подготовка

1. Создайте книгу `.xlsm` с листами `List1` и `List2`.
2. Нажмите `Alt+F11` и через File → Import File импортируйте `cellveilxl.bas`.
3. Создайте ключи из папки проекта:

```powershell
python -m pip install -r keygen/requirements.txt
python keygen/keygen.py --mode production --output production-keys.json
```

Открытый ключ появится в консоли. В JSON сохранятся оба ключа: `public_key` для скрытия и `private_key` для извлечения. Закрытый ключ храните у себя. В Excel вставляйте только строку нужного ключа, сохраняя регистр.

Режим `production` использует X25519. Для демонстрации можно создать короткие ключи с `--mode demo`, установив в модуле `CRYPTO_MODE = "demo"`.

## Настройки

Настройки находятся в начале `cellveilxl.bas`. По умолчанию:

| Настройка | Значение | Назначение |
|---|---|---|
| `CRYPTO_MODE` | `"production"` | Режим, совпадающий с режимом ключей |
| `SCR_SHEET` | `"List1"` | Лист с исходными данными и ключами |
| `HOST_SHEET` | `"List2"` | Лист с документом-носителем |
| `SOURCE_RANGE` | `"A1:B10"` | Диапазон, который нужно скрыть |
| `PUBLIC_KEY_CELL` | `"H1"` | Ячейка открытого ключа |
| `PRIVATE_KEY_CELL` | `"H2"` | Ячейка закрытого ключа |
| `OUTPUT_CELL` | `"D1"` | Начало восстановленного диапазона |
| `HOST_RANGE` | `""` | Область носителя; пустая строка — вся используемая область |

Исходные данные и область восстановления не должны пересекать ячейки ключей.

## Как скрыть и извлечь данные

Чтобы скрыть данные:

1. Заполните `List1!A1:B10`, вставьте открытый ключ в `List1!H1`.
2. На `List2` подготовьте документ с достаточным количеством текста.
3. Через `Alt+F8` запустите `EmbedScr` и сохраните созданную книгу как `.xlsx`.

Если места не хватает, добавьте текст в носитель или уменьшите исходный диапазон. Исходная книга останется у вас.

Чтобы извлечь данные, откройте свою `.xlsm`, вставьте закрытый ключ в `List1!H2`, запустите `ExtractScr` и выберите файл-носитель. Данные появятся с `D1`, заменив существующие значения в области восстановления. Если меняли настройки, используйте свои адреса.

При извлечении должны совпадать режим, `HOST_RANGE` и магические байты, использованные при скрытии. Не меняйте текст, порядок ячеек и оформление носителя: это может повредить данные.

## Что такое магические байты

Магические байты — это короткая метка в начале потока. По ней программа понимает, что нашла свой пакет данных. Первые четыре байта по умолчанию обозначают ASCII-литерал `CVX3`:

```vb
Private Const MAGIC_BYTE_0 As Byte = 67
Private Const MAGIC_BYTE_1 As Byte = 86
Private Const MAGIC_BYTE_2 As Byte = 88
Private Const MAGIC_BYTE_3 As Byte = 51
```

Каждой константе можно задать любое целое число от **0 до 255** включительно. Например, `12, 200, 0, 255` — допустимая последовательность. Байты могут повторяться и не обязаны обозначать печатные символы. Их порядок имеет значение.

Замена этой метки может снизить вероятность обнаружения по известной сигнатуре `CVX3`, но не скрывает другие признаки наличия данных. Это не пароль и не дополнительное шифрование. Для извлечения нужны те же четыре значения в том же порядке; сохраните их вместе с настройками для соответствующего файла.

## Ограничения

Сохраняются текст, Unicode, числа, логические значения, пустые ячейки и числовые форматы, включая даты. Формулы источника восстанавливаются как значения. Ошибки и объединённые ячейки в источнике не поддерживаются. Предел — один прямоугольник до 200000 ячеек и зашифрованный пакет до 1 MiB.

Для носителя подходят обычные текстовые ячейки без полужирного начертания, объединения и условного форматирования. Используются Arial, Calibri, Segoe UI и Tahoma; оставляйте запас места, чтобы текст не обрезался. Рисунки, диаграммы и настройки печати в результат не переносятся.

Шифрование использует AES-256-CTR, но случайные числа берутся из некриптографического генератора Excel `Rnd`, а проверки целостности нет. Поэтому даже режим `production` не стоит считать надёжной защитой конфиденциальных данных. Неверный ключ или повреждение обнаруживаются не всегда; скрытые данные также можно заметить при анализе файла.

## Модуль для DLP

Для согласованных демонстраций есть [Excel-шаблон плана мероприятия](templates/event-plan.xlsx): 160 вымышленных заданий, фильтры, выбор статуса и инструкция по добавлению строк. В нём нет реальных персональных или коммерческих данных. Возможность передачи заполненной копии определяется правилами организации. Шаблон можно пересоздать командой `python templates/create_event_plan.py` после установки зависимостей DLP.

В `keygen/` находится генератор ключей, в `dlp/` — независимый детектор для Python 3.10+. Он анализирует размер и состав XLSX, посимвольное оформление, младшие биты RGB, наклоны и скрытый текст. Отдельный блок распознаёт структуру CellVeilXL даже с изменёнными магическими байтами.

```powershell
python -m pip install -r dlp/requirements.txt
python -m dlp document.xlsx
```

На выходе — JSON с признаками, адресами ячеек, покрытием проверки и двумя оценками риска: общей и для CellVeilXL. Это баллы правил, а не проценты вероятности. Ошибки и превышение лимитов возвращаются как `inconclusive`; решение о блокировке принимает сама DLP. Excel и закрытый ключ не нужны.

Для демонстрации:

```powershell
python -m dlp.demo --output .test-output/dlp-demo
```

Откройте `.test-output/dlp-demo/report.html`: там сравниваются обычный документ, два варианта метки и похожий канал без структуры CellVeilXL. Подробности интеграции, архитектура, тесты и ограничения — в [инструкции модуля](dlp/README.md).
